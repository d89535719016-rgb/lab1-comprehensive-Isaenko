# Отчет по лабораторной работе №1

## 1. Матрица решений (Выбор СУБД)

Для хранения финансовых транзакций и промокодов было проведено сравнение PostgreSQL и MongoDB.

| Критерий | Вес | PostgreSQL | MongoDB |
| :--- | :--- | :---: | :---: |
| Поддержка ACID-транзакций и целостность данных | 0.35 | 5 | 4 |
| Производительность чтения | 0.20 | 4 | 5 |
| Гибкость схемы (разные виды промокодов) | 0.15 | 4 | 5 |
| Стоимость владения | 0.10 | 5 | 4 |
| Экосистема и зрелость (SQL, отчёты, специалисты) | 0.20 | 5 | 4 |
| **Взвешенная оценка** | **1.00** | **4.65** | **4.35** |

**Вывод:** По результатам расчетов побеждает PostgreSQL (4.65 против 4.35). Самый высокий вес был установлен для критерия ACID-транзакций (0.35), так как в работе с финансовыми данными недопустима потеря транзакций или частичное применение изменений. PostgreSQL гарантирует надежность "из коробки", а требования к гибкости схемы при необходимости можно реализовать с помощью типа данных JSONB.

## 2. Инфраструктура и ветвление

В ходе работы была выстроена следующая структура проекта:
* Созданы ветки `main`, `develop`, а также компонентные ветки для задач.
* Настроена защита ветки `develop` (Require a pull request before merging, обязательные апрувы установлены в 0, так как одобрение автора недоступно на GitHub).
* Созданы конфигурационные файлы `.editorconfig` для стандартизации форматирования (отступы в 4 пробела, кодировка UTF-8) и `.github/CODEOWNERS`.

## 3. Качество кода (Линтинг)

* Внедрен статический анализатор кода `flake8` через GitHub Actions.
* В рамках ветки `feature/qa-gates` были обнаружены и успешно устранены ошибки оформления кода в файле `src/discount.py` (включая неиспользуемые импорты `import os` и скрытые пробелы в пустых строках `W293`).
* Настроен автоматический запуск проверок (CI) при создании Pull Request.

## 4. Архитектурное проектирование

* В сервисе draw.io спроектирована UML-диаграмма классов, описывающая взаимодействие `DiscountService` (метод `calculate_discount`) и `TransactionRepository` (метод `save_transaction`).
* Диаграмма успешно интегрирована в репозиторий.
* При слиянии архитектурной ветки был сформирован и пройден чек-лист код-ревью.
